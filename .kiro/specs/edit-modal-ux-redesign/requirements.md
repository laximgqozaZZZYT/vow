# 要件定義書

## はじめに

本ドキュメントは、vow習慣管理アプリケーションにおける編集モーダル（Habit、Goal、Sticky）のUI/UXリデザインに関する要件を定義します。データスキーマは変更せず、レイアウトとユーザー体験のみを改善することを目的とします。

## 用語集

- **Modal**: ユーザーがエンティティ（Habit、Goal、Sticky）を作成・編集するためのオーバーレイダイアログ
- **Combobox**: 検索可能なドロップダウン選択UIコンポーネント
- **Chip**: 選択されたアイテムを表示する小さなラベル型UIコンポーネント
- **Sticky_Footer**: スクロール位置に関係なく常に表示される固定フッター
- **Collapsible_Section**: 展開・折りたたみ可能なセクション
- **Tag_Selector**: タグを検索・選択するためのコンポーネント
- **Related_Entity_Selector**: 関連するGoalやHabitを選択するためのコンポーネント

## 要件

### 要件 1: スマート選択UI（Combobox）の導入

**ユーザーストーリー:** ユーザーとして、タグや関連エンティティを効率的に選択したい。全候補を一覧表示せず、検索入力をメインインターフェースとして使用できるようにしたい。

#### 受け入れ基準

1. WHEN ユーザーがTag_Selectorにフォーカスする THEN システムは検索入力フィールドと選択済みChipのみを表示するSHALL
2. WHEN ユーザーが検索文字列を入力する THEN システムは入力に一致する候補をドロップダウンで表示するSHALL
3. WHEN ユーザーが候補を選択する THEN システムは選択済みChipとして表示し、ドロップダウンを閉じるSHALL
4. WHEN 選択済みChipの削除ボタンをクリックする THEN システムはそのアイテムを選択解除するSHALL
5. WHEN Related_Entity_Selectorを表示する THEN システムは最大5件の「最近使用したアイテム」をサジェストとして表示するSHALL

### 要件 2: セクション階層と整理

**ユーザーストーリー:** ユーザーとして、主要な入力項目（名前、説明、主要タグ）をスクロールなしで完了したい。詳細設定は必要な時だけ展開できるようにしたい。

#### 受け入れ基準

1. WHEN Habitモーダルを開く THEN システムは「Workload」と「Timings」セクションをデフォルトで折りたたんだ状態で表示するSHALL
2. WHEN ユーザーがCollapsible_Sectionのヘッダーをクリックする THEN システムはそのセクションの展開・折りたたみ状態を切り替えるSHALL
3. WHEN 画面幅が十分にある場合 THEN システムは「Unit」と「Load per Count」を横並び（2カラム）で表示するSHALL
4. WHEN Goalモーダルを開く THEN システムは主要項目（名前、詳細、期日）を最上部に配置するSHALL
5. WHEN Stickyモーダルを開く THEN システムは関連Goal・Habit選択をCollapsible_Sectionとして表示するSHALL

### 要件 3: 視覚的優先度の確立

**ユーザーストーリー:** ユーザーとして、現在どのGoal・Habitが関連付けられているかを即座に把握したい。選択状態と未選択状態を明確に区別できるようにしたい。

#### 受け入れ基準

1. WHEN アイテムが選択されている THEN システムはアクセントカラーを適用したChipとして表示するSHALL
2. WHEN アイテムが未選択である THEN システムは控えめなスタイル（muted背景）で表示するSHALL
3. WHEN ダークモードが有効である THEN システムは最適化されたコントラストで選択状態を表示するSHALL
4. WHEN 選択済みChipにホバーする THEN システムは削除アクションを示す視覚的フィードバックを提供するSHALL

### 要件 4: 固定フッター（Sticky Footer）

**ユーザーストーリー:** ユーザーとして、スクロール位置に関係なく保存・キャンセル・削除ボタンに常にアクセスしたい。

#### 受け入れ基準

1. WHILE モーダルがスクロール可能な状態である THEN システムはアクションボタン（保存、キャンセル、削除）を固定フッターとして表示するSHALL
2. WHEN 固定フッターを表示する THEN システムはコンテンツ領域との境界を示す視覚的区切り（シャドウまたはボーダー）を表示するSHALL
3. WHEN モーダルコンテンツがスクロールされる THEN システムは固定フッターを常に可視状態に維持するSHALL
4. WHEN 削除ボタンを表示する THEN システムは誤操作防止のため他のボタンと視覚的に分離するSHALL

### 要件 5: 関連エンティティ選択の改善

**ユーザーストーリー:** ユーザーとして、関連するGoalやHabitを効率的に選択・管理したい。大量のチップが平置きされる状態を避けたい。

#### 受け入れ基準

1. WHEN Related_Entity_Selectorを表示する THEN システムはマルチセレクトドロップダウン形式で表示するSHALL
2. WHEN 関連エンティティが選択されている THEN システムは選択済みアイテムをコンパクトなChipリストで表示するSHALL
3. WHEN ドロップダウンを開く THEN システムは検索フィルター機能を提供するSHALL
4. WHEN 関連エンティティがない場合 THEN システムは「関連なし」の状態を明確に表示するSHALL
5. WHEN 関連Habitを選択する THEN システムはHabitの種類（do/avoid）を視覚的に区別するSHALL

### 要件 6: レスポンシブ対応

**ユーザーストーリー:** ユーザーとして、モバイルデバイスでも快適にモーダルを操作したい。

#### 受け入れ基準

1. WHEN 画面幅が768px未満である THEN システムは2カラムレイアウトを1カラムに変更するSHALL
2. WHEN モバイルデバイスで表示する THEN システムはタッチターゲットを最小44x44pxで維持するSHALL
3. WHEN モバイルデバイスでモーダルを表示する THEN システムはモーダル高さを画面の95%以下に制限するSHALL
4. WHEN 固定フッターをモバイルで表示する THEN システムはボタンを縦並びまたは適切なサイズで表示するSHALL

### 要件 7: アクセシビリティ

**ユーザーストーリー:** ユーザーとして、キーボードやスクリーンリーダーでモーダルを操作したい。

#### 受け入れ基準

1. WHEN Comboboxにフォーカスがある THEN システムはキーボードナビゲーション（上下矢印、Enter、Escape）をサポートするSHALL
2. WHEN Collapsible_Sectionを操作する THEN システムは適切なaria属性（aria-expanded、aria-controls）を設定するSHALL
3. WHEN フォーカス可能な要素にフォーカスする THEN システムはfocus-visibleスタイルを適用するSHALL
4. WHEN モーダルを開く THEN システムはフォーカストラップを実装するSHALL

### 要件 8: 既存機能との互換性

**ユーザーストーリー:** ユーザーとして、既存のNormal/Detailビュー切り替え機能を引き続き使用したい。

#### 受け入れ基準

1. WHEN Habitモーダルを開く THEN システムは既存のNormal/Detailビュー切り替えを維持するSHALL
2. WHEN Normalビューを選択する THEN システムは主要項目のみを表示し、詳細設定を折りたたむSHALL
3. WHEN Detailビューを選択する THEN システムはすべての設定項目を展開状態で表示するSHALL
4. WHEN ビューモードを切り替える THEN システムはユーザーの選択をlocalStorageに保存するSHALL
